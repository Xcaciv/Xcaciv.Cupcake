## 2. [MINOR] §11.2 Q-48; body at §9 NFR-12

**Problem:** §9 NFR-12 is QUIRK-tagged ("Two concurrent downloads to the same target path corrupt each other": create-or-truncate semantics with no lock and nothing serialising two downloads of the same file) and explicitly notes it is "a defect a clone finishing that feature will inherit". Q-48 records unconditional overwrite but not the concurrency case, so a team that resolves Q-48 by adding verification still ships the race.

**Required fix:** Extend Q-48's quirk text to "…Downloads overwrite their target unconditionally with create-or-truncate semantics and no lock, so two concurrent downloads to the same path corrupt each other; package identity is taken from inside the downloaded archive, and nothing verifies a signature, checksum or publisher before the code is loaded." and change its § column to `7.7, 7.10, 9`.
