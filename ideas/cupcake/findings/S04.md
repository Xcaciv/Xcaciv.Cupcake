## 1. [MAJOR] §4 Glossary, "Verified Directory rule" row

**Problem:** The glossary defines it as "The safety rule that a Plugin Directory must exist and resolve **inside a restricted root** before it is scanned." That is the pre-correction claim eight other locations explicitly forbid: §6 GR-48 ("A clone must not restate this as 'the Plugin Directory must be inside the working directory' — that is the rule the code appears to intend and is not the rule it implements"), §7.4 FR-4.20 ("Do not restate this rule as … that is the wrong claim and it under-states the exposure"), §5.3 ET-17 ("Critical, and do not copy as-is"), §7.1 FR-1.84, §7.2 FR-2.10, §7.6 FR-6.30, §7.10 FR-10.45, §7.11 FR-11.10. Under the corrected rule the candidate's *parent* is tested and the boundary's final segment is ignored, so a sibling tree resolves outside the restricted root and is still accepted — the glossary definition is false by the document's own finding, and it is the definition a reader meets first for a security-relevant boundary.

**Required fix:** Replace the definition with: "The safety rule applied to a Plugin Directory before it is scanned: it must exist, be a directory, and have a **parent** that passes a containment test against a boundary defaulting to the process working directory — a test that ignores the boundary's own final segment, so the effective boundary sits one level **above** the working directory (siblings accepted, the working directory itself rejected). See §6 GR-48. A directory failing the check is silently skipped."
